# preorder 태스크 용량 계약 (preorder → 대기열)

preorder 의 태스크마다 살아 있다는 표시와 초당 접수 용량을 공유 Redis 에 적는다. 대기열은 전체 입장 속도를 "살아 있는 태스크 용량의 합" 으로 잡는다 — 늘어난 태스크만큼 바로 더 들이고, 줄어든 태스크만큼 바로 덜 들인다. 문서와 어긋나는 쪽이 고친다.

## 위치

| 항목 | 값 |
| --- | --- |
| Redis | preorder 가 쓰는 `spring.data.redis`(지금은 모든 서비스가 같은 클러스터). 대기열이 다른 클러스터로 옮기면 이 키는 preorder 클러스터에서 읽는다 |
| 키 | `preorder:capacity:tasks` (해시 하나) |
| 필드 | 태스크 ID. 태스크가 뜰 때마다 새로 만든다(재시작한 태스크는 새 행) |
| 값 | `마지막시각\|처음시각\|초당용량\|판정초` — 예: `1761098400\|1761098280\|100\|15` |

- **시각**은 Redis `TIME` 의 초(epoch)다. 태스크 시계가 아니라 Redis 시계로 적으므로, 읽는 쪽도 Redis `TIME` 과 비교한다.
- **처음 시각**은 그 태스크가 처음 적은 때다. 갓 뜬 태스크(JIT · 커넥션 풀 · 캐시가 덜 데워진 상태)의 몫을 낮게 잡을 때 쓴다.
- **초당 용량**은 태스크 하나가 버티는 초당 접수 수다(`nova.capacity.heartbeat.accept-per-second`, 1 이상 정수).
- **판정초**는 `지금 − 마지막시각` 이 이것을 넘으면 죽은 태스크로 보라는 값이다(`stale-after`, 기본 15 — 적는 주기 5초의 세 배).

## 동작

- preorder 는 5초마다(`interval`) 제 행을 적고, 같은 스크립트에서 판정초를 넘긴 행을 지운다. 내려갈 때는 제 행을 지운다.
- 적기에 실패해도 접수는 그대로 받는다. 실패가 판정초보다 길어지면 다른 태스크가 그 행을 지운다.
- 끄면(`nova.capacity.heartbeat.enabled=false`) 아무 행도 적지 않는다. 대기열은 행이 하나도 없으면 고정 입장 속도(운영값)로 돌아간다.

## 대기열이 읽는 법

1. `HGETALL preorder:capacity:tasks` 와 `TIME` 을 읽는다.
2. 모양이 맞지 않는 값, `지금 − 마지막시각 > 판정초` 인 행, 마지막시각이 지금보다 뒤인 행은 버린다.
3. 남은 행의 초당 용량을 더한 값이 전체 입장 속도의 상한이다. 처음 시각이 최근인 행은 몫을 낮게 잡는다(예: 1~2분 동안 절반).
4. 행은 있는데 살아 있는 행이 없거나 키를 읽지 못하면 직전 합을 그대로 쓴다 — preorder 가 위태로울 때 운영값으로 뛰지 않게. 직전 합을 모르면(리더가 바뀜) 운영값이다.
5. 사전예약 하나의 상한은 태스크 수와 무관하다 — 같은 회차의 접수는 회차 행 잠금 하나에 줄 선다. 회차 하나의 처리량은 별도 운영값으로 둔다.

행을 지우는 것은 preorder 만 한다. 대기열은 읽기만 한다.
